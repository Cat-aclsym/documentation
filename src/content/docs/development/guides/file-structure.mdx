La racine est `res://`.

Le workflow CI est dans `.github/workflows/build.yml`.

## Règle de placement

- Une scène et son script partagent le même dossier.
- Une logique sans scène va dans `core/`, `autoloads/` ou `ui/components/`.
- Le nom du fichier de la scène d'une entité est son id de `stats.json`: `default_zombie.tscn`, `bat_01.tscn`.
- Les données JSON, `stats.json` compris, sont dans `data/`.
- `tests/` reprend l'arborescence des sources: un test de `game/enemies/` va dans `tests/game/enemies/`.
- Les noms de fichiers sont en `snake_case`.

## Fichiers générés ou ignorés par Git

- `log/` : écrit dans `res://log`, donc seulement depuis l'éditeur ([Logs](/documentation/development/guides/logger/)).
- `*.translation` : générés à l'import à partir de `translations.csv`, déclarés dans `project.godot`. Dialogic ne génère pas de fichiers de traduction: les timelines sont une par langue.
- `reports/`: rapports JUnit et HTML de gdUnit4.
- `exports/` et `.godot/`.

## Où créer quoi

- Entité du jeu (ennemi, tour, piège, projectile, carte, niveau) : `game/...`, avec son script dans le même dossier
- Menu, widget ou popup : `ui/...`, avec son script dans le même dossier
- Logique sans scène : `core/...`, `autoloads/...` ou `ui/components/...`
- Service global : `autoloads/...`
- Commande de console : `debug/console/commands/...`
- Test unitaire : `tests/...`, dans le dossier qui reprend celui de la source testée
- Niveau ou challenge : `data/levels/...` et `data/challenges/...` (les arcs sont dans `level_selection_menu.tscn`)
- Stats d'une tour, d'un piège ou d'un ennemi : `data/stats.json`
- Nom affiché d'une tour, d'un piège ou d'un ennemi : `assets/translations/translations.csv`

Les étapes pour ajouter un ennemi, une tour, un piège, un niveau, un défi ou une commande sont dans [Recettes](/documentation/development/guides/recipes/).
